# Unicode割り当て・フォント情報・文字セット

## Unicode割り当て

- 🟢 [Done] 右側メトリクスの「Unicode割り当て」から、選択した既存グリフへ16進コードポイントや範囲を指定する。例: `U+0041 U+FF21 U+20000`。
- 🟢 [Done] 複数スカラーを1つのグリフへ割り当てる別名マッピングに対応。入力を空にして適用すると未割り当てに戻す。これは文字列・合字・異体字のシーケンスマッピングとは異なる。
- 🟢 [Done] 他グリフとの重複を拒否し、元のグリフから割り当てを奪わない。.notdefは変更不可。無効なUnicode・上限超過・古いrevisionは文書を変更しない。
- 🟢 [Done] グリフID・名前・CID・輪郭・送り幅・制作状態を保持し、変更を1回のUndoにまとめる。既存名がuniXXXXであっても、割り当て解除後のType1/CFF出力では中立的なglyph名を使い、再読み込み時に旧名から対応が復活しないようにする。
- 🟢 [Done] 保存JSON・自動復旧・TTF/OTFのcmap・Type1/CFFの名前によるマッピングへ反映。Type1/CFFの複数別名は従来どおり出力時に輪郭を複製する。

## フォント情報

メイン画面上部の情報アイコンから開く。

- 🟢 [Done] ファミリー名、スタイル、太さ（0〜1000）、幅区分（0〜9）、斜体角（−90〜90）、太字・斜体フラグ、著作権、ライセンス、ライセンスURLを編集する。0の太さ・幅区分は既存データの未指定値を保持するために許可する。
- 🟢 [Done] 変更全体を1回のUndoにする。輪郭の編集・文字追加・割り当て変更と同じ履歴に入り、Redoにも対応。履歴のためにフォント全体を複製せず、小さなメタデータだけを保持する。
- 🟢 [Done] ダイアログを開いた時点のepoch/revisionで適用を検証する。他ウインドウ等で文書が変わった場合は古い内容を適用しない。閉じて開き直すと現在値から編集できる。
- 🟢 [Done] ファミリー名と情報をJSON・自動復旧へ保存し、TTF/OTFのname、OS/2、head、post等へ既存の出力処理を通して反映。PostScript系では表現可能なFontInfo/Noticeのみを出力する。すべての形式で全項目を保持できるとは限らない。
- UPM・全体の上下メトリクス・CIDの登録情報はこの画面では変更しない。UPM変更時の輪郭スケーリングや全OpenTypeメタデータの編集は 🔴 [Later]。

## プリセット

左の文字一覧の「＋」から文字セットを選び、隣の追加アイコンを押す。範囲と件数はRust側で管理し、GUIには英語・日本語・简体中文の名称を表示する。

| プリセット | 対象文字数 |
|---|---:|
| 基本ラテン文字 | 95 |
| ラテン文字＋Latin-1 | 191 |
| ひらがな | 93 |
| カタカナ | 112 |
| かな・句読点 | 460 |
| CJK統合漢字 | 20,992 |
| CJK拡張A | 6,592 |
| CJK拡張B | 42,720 |

- 🟢 [Done] 登録済みの文字は保持し、不足分だけ空グリフとして追加。重複適用は変更なしとなり、Undo履歴を増やさない。追加全体は1回のUndo。
- 🟢 [Done] プロジェクト全体65,535グリフ（.notdefを含む）まで。複数セットの合計が上限を超える場合は部分的に追加せず、全体を拒否する。
- CJKはUnicode範囲であり、JIS・GB等の国別文字セットや常用漢字の収録を保証するプリセットではない。規格別セットは 🔴 [Later]。

## 検証

Rustテスト217件、Clippy `-D warnings`、型検査・フロントエンドビルド成功。重複・解除・Unicode別名・CID保持、メタデータと輪郭編集を混在させたUndo/Redo、JSON/TTF/OTF/PFB/CFFの保存往復、プリセットの既存輪郭保持・重複適用・容量超過の原子性を検証した。

macOSの独立した検証アプリでAへU+0041/U+FF21/U+20000を割り当て、Bとの衝突拒否を確認。フォント名・スタイル・太さ・幅・著作権・ライセンス・URLを適用し、Undo/Redoでフォント名が戻ることを確認した。ひらがなプリセットを追加してJSON保存し、158グリフ（.notdefを除く）、元のAの2輪郭と別名、メタデータが保持されることをファイルで確認した。
