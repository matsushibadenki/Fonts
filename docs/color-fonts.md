# カラーフォント

フォントライブラリでファイルを選ぶか既存の書体を選択し、パレットのアイコン「カラーフォント」を開く。カラー形式は一覧にも表示する。英語・日本語・简体中文に対応する。読み込み時の元データはRustに保持し、プレビューや出力の途中で元ファイルが外部変更されても読み込み済みのデータを利用する。

## 対応範囲

| 形式 | 読み込み・形式表示 | プレビュー | 単体フォント出力 |
| --- | --- | --- | --- |
| COLR/CPAL v0（TrueType・CFF） | 🟢 [Done] | 🟢 [Done] パレット選択・アルファ合成 | 🟢 [Done] 全パレットを保持 |
| sbix・CBDT/CBLC | 🟢 [Done] | 🟢 [Done] PNGストライク。対応する非PNGビットマップはFreeType経由 | 🟢 [Done] 全ストライクを保持 |
| COLRv1 | 🟢 [Done] | 🟢 [Done] パレット・グラデーション・変形・合成 | 🟢 [Done] ペイント・可変情報を保持 |
| SVG-in-OpenType | 🟢 [Done] | 🟢 [Done] 静的ベクター・色・透明度・gzip・CPAL。[対応範囲](svg-preview.md) | 🟢 [Done] SVGテーブルを保持 |
| TTC/OTC内のカラーフェイス | 🟢 [Done] フェイス単位 | 🟢 [Done] 上記形式に従う | 🟢 [Done] 選んだフェイスのみTTF/OTFへ抽出 |

プレビューは文字列（1〜64文字）・サイズ（12〜192）・CPALパレットを指定して実行する。メインキャンバスへ表示し、閉じるアイコンで通常の編集へ戻る。既存文書の輪郭・Undo履歴・保存データを変更しない。文書が切り替わるなど、処理開始後に文書や描画世代が変わった結果は適用しない。

COLRv0は同梱FreeTypeでラスタライズする。COLRv1は同梱HarfBuzz 15.0.0のpaint/rasterを使い、線形・放射・円錐グラデーション、繰り返し／反射、透明度、変形、クリップ、レイヤー合成を処理する。CPALの選択と前景色（黒）を渡す。出力範囲を先に固定し、フォントの境界値から無制限の画像を確保しない。premultiplied BGRAをstraight RGBAへ変換して保持する。ビットマップのPNGは既存のRust画像デコーダーで上限付きで読み込む。FreeTypeへの外部libpng追加は不要。Rust側でRGBAを保持し、wgpuテクスチャとして描画する。画像・輪郭・フォントの大容量データをWebViewへ転送しない。IPCは設定、書体情報、保存・検証結果のみ。

可変カラーフォントは既定の軸値でプレビューし、出力では元の可変テーブルを保持する。プレビューはUnicode→グリフの対応を使い、高度な組版、絵文字のZWJ・異体字・国旗シーケンスの合成は実行しない。未収録文字の件数を設定画面へ返す。複雑なサンプルが描画領域を超えた場合はサイズか文字数を減らす案内を表示する。最大プレビューは2048×1024、各ビットマップは2048×2048、元ファイルは256MiBまで。

## 出力と検証

「カラーを保持して出力」でネイティブ保存ダイアログを開く。元の輪郭種別に合わせてTTFまたはOTFを保存する。パレット選択はプレビュー専用であり、出力では元の全パレット・カラー情報を保持する。GSUB/GPOS、hinting、ビットマップ、可変テーブル、名前・ライセンスを含め、元のテーブル内容を保持する。無効になるデジタル署名DSIGだけを除外し、sfntディレクトリーとheadのチェックサムを再構築する。元ファイルは読み取り専用として扱い、既定名には「-Color」を付ける。

拡張子、既存ファイルとの衝突、保護ディレクトリーを共通ルールで確認し、原子的に保存する。キャンセルは出力完了と扱わない。保存前に出力を再解析し、テーブル数・元の各テーブルとの一致（headのchecksumAdjustment以外）・全体チェックサム・各テーブルのチェックサムを検証する。保存後にもファイルを読み戻し、全バイトの一致と再検証を行う。完了画面は保存先とサイズを表示する。この検証は保持と構造の検証であり、全組版エンジンでの表示保証ではない。

通常の編集用モデルは単色輪郭であるため、カラーフォントの「コピーを編集」「通常変換」を無効にする。バックエンドでも通常読み込み・一括変換・可変フォントの静的化でカラー情報を暗黙に落とさず、専用のカラー入出力を案内する。カラーの編集、プロジェクトへのカラー情報保存・復旧は将来項目。カラーWOFF2出力は対応済み。

## 検証

テスト素材は独自の幾何学輪郭と画像から生成したMIT素材。COLRv0の複数パレット・半透明、CFF、sbixとCBDTのPNG、COLRv1、SVG、コレクションのフェイス抽出、全テーブル保持、破損出力の拒否、設定の境界を自動検証する。生成用のFontTools/Pythonは開発専用で、アプリ実行時には不要。

⭕️ [Pending] Windows/Linux実機でのGPU・保存ダイアログ、各外部組版アプリでの表示検証。

🟢 [Done] Rustテスト339件成功（既存の重い任意検証5件はignore）、Clippy `-D warnings`、TypeScript/Viteビルド成功。macOSの独立検証アプリで三言語、COLRv0の赤／紫と緑／黄のパレット切り替え、wgpu描画、ネイティブ保存、保存後の検証完了表示を確認した。COLRv1ではプレビューが無効で、カラー保持出力は利用可能と明示されることを確認した。

## カラーWOFF2（2026-11-03）

カラー専用画面の出力形式で「Webフォント (.woff2)」を選ぶ。圧縮は高速・標準・サイズ優先・最大圧縮。元の輪郭形式を保つため、TrueType/CFFの変換指定は行わない。パレット選択はプレビュー専用で、出力には全パレットを保持する。

元のCOLR/CPAL、SVG、sbix、CBDT/CBLC、組版・可変テーブルを含め、DSIGを除く全テーブルを保持する。WOFF2のhead bit 11とcheckSumAdjustmentだけを許可し、復号後の全テーブルとチェックサムを元ファイルに照合する。保存ダイアログで拡張子・元ファイル・保護フォルダーを検査し、保存後の読み戻しが成功した場合だけ検証完了を表示する。

ブラウザーが各カラー形式を表示できるかはブラウザー側の対応に依存する。COLRv1とSVGの静的ベクタープレビューは対応済み。SVGの未対応要素は三言語で明示する。カラーWOFF2自体には外部依存を追加していない。検証範囲はROADMAP参照。

🟢 [Done] macOSのwgpu実GPUから色・向き・透明度・sRGB・パレット切替を読み戻して検証。Chromiumの同一フォント描画との比較は41,948画素で最大チャンネル差1/255。三言語のダイアログをPlaywrightで操作し、パレット2→プレビューのIPC要求、当時未対応だったSVGの無効表示（今回のSVG対応で有効化済み）、幅920／560pxでのはみ出しなし・実行時エラーなしを確認。UIのIPCは模擬であり、ネイティブ画面全体の手動検証とは区別する。

開発用のPNG出力: `cargo run -p font-core --example color_preview -- FONT.ttf OUTPUT.png ABC 0`。末尾のパレットは0始まり。アプリにはCLIや実行時Pythonを追加しない。新しい外部依存はなく、HarfBuzzの上流著作権・ライセンスは既存の第三者告知に収録済み。
