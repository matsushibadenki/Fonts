## 操作

1. メトリクスの「クラスカーニング」で左クラス／右クラスを選ぶ。
2. 新規クラスに名前と所属グリフを入力し、チェックアイコンで保存する。所属は `A T`、`AT`、`uni0041 uni0054`、`#1 #2` のように指定できる。`#ID`は文書内のグリフID。空白・カンマで区切り、Unicode未割り当てのグリフにも対応する。
3. 既存クラスを選ぶと名前・所属を編集できる。ごみ箱でクラスと、それを参照するクラスペアをまとめて削除する。個別のグリフペアは独立した設定として残る。
4. 下部で左クラス・右クラスを選び、調整量を適用する。負で詰め、正で広げ、0でクラスペアを削除する。登録済みの行から値を再編集・削除できる。
5. 目のアイコンで所属グリフの組合せを試し組みする。左右各4文字まで、最大16組を表示する。Unicodeのないグリフは文字列の試し組みから除外する。通常の試し組み文字列でもクラス値が有効になる。

同じ側では1グリフにつき1クラス。左右で同じグリフが所属することはできる。クラス名は同じ側で一意にする。登録後の所属表示は、曖昧さを避けて `#ID` で示す。

## ペアの優先順位

**明示グリフペア → クラスペア → 0** の順に値を選び、加算しない。

ペアカーニング欄ではクラス由来の値を表示する。「0の例外ペア」アイコンは明示的な0を登録し、そのグリフ間だけクラス調整を無効にする。通常のペア適用で0を指定するか、ペアを削除すると例外がなくなり、クラス値へ戻る。

例: 左クラス `A T`、右クラス `V W` が−80の場合、AVの明示ペアを+20にするとAVは+20、AWを0の例外にするとAWは0、TVとTWは−80になる。

## 文書・履歴

- Rustの`class_kerning`に安定ID・名前・所属・クラスペアを保持する。空の設定はJSONから省略し、従来のプロジェクトは空として読む。明示0の例外は`kerning`に保存する。
- 最大64クラス／側、所属合計2048グリフ／側、クラスペア4096件。クラス名は80文字、調整値は−32768〜32767の整数。
- 空クラス、同じ側の所属・名前の重複、存在しないグリフ、.notdef、無効なID・順序・参照を拒否する。
- 1回の登録・変更・削除は1回のUndo。クラス削除と関連クラスペアの削除は原子的に実行し、Undoで一緒に復元する。同値操作は履歴を増やさない。
- epoch／revisionと未確定編集を検査する。各ウインドウはRust文書に命令を送り、クラスを独自に所有しない。クラス所属のID要約のみをWebViewへ渡し、輪郭やGPUデータは転送しない。
- 通常のJSON保存・再読込と復旧チェックポイントに接続する。

## 試し組み・フォント出力

試し組みの抽出では、残るグリフに所属を絞り、空になったクラスとそのクラスペアを除外する。出力用の密なグリフIDへ付け替え、生成TTFを再取り込みした文書の値で配置する。AVアイコンで明示ペア・クラス・例外をまとめてON/OFFでき、固定見本には当時の所属と値が残る。

TTF／OpenType CFF／OpenType CID-CFFは、DFLT scriptの`kern` featureにGPOS Lookup Type 2を1つ出力する。明示ペアのPairPos Format 1を先に、クラスのPairPos Format 2を後に置く。同じlookup内で最初に一致するsubtableを使い、0の例外も含めて優先順位を維持する。クラスを個別ペアへ大量展開しない。[OpenType GPOS仕様](https://learn.microsoft.com/en-us/typography/opentype/spec/gpos#pair-adjustment-positioning-format-2-class-pair-adjustment)に従う。

このアプリが出力する限定的なGPOS構造は再取り込みできる。GPOSにはクラス名や編集用IDがないため、再取り込み時は`Left 1`／`Right 1`等の名前と新しいクラスIDを割り当てる。元の名前・IDを保持する保存形式はプロジェクトJSON。クラスペアが全くない場合、未使用クラスのみをGPOSへ出力することはしない。

クラスペアがある文書を単体CFF／CID-CFF、PFA／PFB、CID Type1へ書き出すと、設定を黙って捨てず、TTF／OTFを促すエラーを表示する。CMap出力は文字対応表のみであり影響しない。
