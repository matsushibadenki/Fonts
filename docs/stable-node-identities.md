# 安定node IDと永続UUID

## 保存形式と参照

🟢 [Done] プロジェクトschema version 2は文書、輪郭、端点、制御点にUUID v4を保存する。`NodeRef { document, node }`から現在のグリフ・輪郭・点アドレスを解決するため、配列番号が変わっても同じ点を参照できる。輪郭のUUIDからも現在位置を解決できる。Rustが正本を所有し、UIには参照と状態のみ渡す。

旧v1は読み込み時にIDを付けてv2へ移行し、未保存として開く。明示保存まで元ファイルを変更せず、復旧コピーにも移行後のIDを保存する。保存・再読み込み、復旧、Undo/RedoでIDを保持する。Undo履歴そのものは従来どおりメモリ内で、再起動時には再開しない。旧アプリはv2を読み込めない。

新規文書・独立したフォント読み込みには新しい文書UUIDを生成する。「別名で保存」やプロジェクトファイルの複製は同じ文書系統のUUIDを維持する。UUIDはフォントのTTF/OTFテーブルへ出力しない。

## 編集時の規則

- 点の挿入では既存の端点を保持し、新しい点に新規IDを付ける。三次曲線の分割では元の外側ハンドルIDを左右へ引き継ぎ、二次曲線の制御点IDは左側に残す。
- 点の削除は削除対象と消えた制御点の参照を無効にし、それ以外を維持する。削除した参照は解決失敗となり、Undoで再び解決できる。
- 反転は座標に対応する点・制御点IDを移動する。分割は元の切断点IDを片側へ残し、複製された端点に新規IDを付ける。元の輪郭IDは片側へ残り、もう片側に新規IDを付ける。
- 連結では両輪郭のIDを別名として保持する。同位置の端点を統合すると両端点IDを同じ点へ解決する。閉鎖時に重なる始終点も同様。再び開くと新しい終点には新規IDを付ける。
- 線から曲線への変更では残る制御点IDを保持し、追加した制御点に新規IDを付ける。
- スニペット登録・独立コピー配置は元のIDを流用しない。ブール演算の再構築で消えた点の参照は無効になる。どちらもUndoで元の輪郭・IDを復元する。

編集確定時に欠けたIDを補完し、nil・重複・構造不一致・過大な別名リストを拒否する。単一グリフの通常編集で文書全体を複製しない。操作中の一時的な番号はrevision検証と併用する。UIの点選択は文書UUIDとnode UUID、連結対象は輪郭UUIDを使い、挿入や並べ替えで別の対象を選ばない。参照切れのエラーは英語・日本語・简体中文に対応する。
