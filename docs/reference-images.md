## 操作と画面

「画像」アイコン群に、配置・選択／変形・表示／非表示・ロック・削除をまとめる。ノード編集など他の機能群とは区切り線で分ける。説明は情報アイコンのツールチップで表示し、英語・日本語・简体中文に対応する。

- 配置: ネイティブファイル選択でPNG／JPEGを読み込み、現在のグリフの編集範囲に縦横比を保って収める。元の画像ファイルを変更せず、プロジェクトへ取り込む。
- 選択: 画像選択／変形ツールを使用する。ノード編集・ペン使用中は画像がクリックを奪わない。複数画像は一覧からも選べ、重なり順を変更できる。
- 位置: 選択画像をドラッグして移動する。数値欄で中心X・Yも入力できる。
- サイズ: 画像の回転に追従するバウンディングボックスと8つのハンドルを表示する。四隅は縦横比を保持し、Shift併用で自由拡縮する。辺のハンドルは対応する幅または高さを変更する。反対側のハンドルを固定して拡縮し、幅・高さの数値入力も用意する。サイズは正の値に制限し、反転は初期実装に含めない。
- 角度: ボックスの外側に回転ハンドルを設け、画像の中心を軸に回転する。Shift併用で15°刻みにスナップし、角度の数値入力にも対応する。
- 透明度: 0〜100%のスライダーと数値入力で設定する。画像だけに適用し、選択枠・輪郭・ガイドは薄くしない。透明度0%でも一覧から選択・削除できる。
- 削除: 選択画像の削除アイコン、または文字入力欄にフォーカスがない場合のDelete／Backspaceで配置を取り除く。元の画像ファイルは削除しない。Undoで画像と設定を復元できる。
- 表示・ロック: 非表示は一時的にアタリを隠す。ロックは誤移動を防ぎ、一覧から解除できる。隠した画像・ロックした画像の位置や透明度も文書に保持する。

ズーム・パンは文書上の配置を変えない。グリフ切替時はそのグリフの画像を表示し、選択・操作途中の変形は終了させる。変形中のEsc／ポインターキャンセルは開始前へ戻す。移動・拡縮・回転・透明度の連続操作は、各ドラッグの確定を1回のUndoにまとめる。数値変更・配置・削除もUndo/Redoに接続する。

## データと処理の所有

Rust側のDocumentに、画像資産とグリフごとの配置を持たせる。各配置はID、asset ID、中心位置、幅・高さ、角度、透明度、表示状態、ロック状態、重なり順を保持する。位置・寸法はフォント単位（Y-up）、角度は反時計回りの度数で保存する。画像ピクセルのY-downとの変換はRendererが担当する。

Tauriの各ウインドウは文書を所有しない。選択やドラッグ中のプレビューもRustのStateで共有し、コマンドにepoch/revisionを付けて古い状態からの変更を拒否する。WebViewは操作命令と小さな状態だけを通信し、画像のデコード・ピクセル・GPUテクスチャをRust/GPU側に保持する。描画と変形枠はwgpuで実装する。

読み込みはワーカーで行い、対応形式、ファイルサイズ、画像寸法、デコード後のメモリ予算を確認してから文書へ追加する。上限やデコードエラー時は既存の文書を保持する。実装済みの上限は1ファイル32MiB、各辺8192px、1画像1600万画素。プロジェクトとUndo履歴が保持する固有資産を合わせて256件・圧縮画像96MiB・RGBA画素256MiBまでとする。配置は1グリフ64件、文書全体8192件まで。上限を超える追加は履歴を勝手に消さず拒否する。

Base64の増分を含め、圧縮画像96MiBは保存時に約128MiBとなり、輪郭などを含めたプロジェクト全体には従来の512MiB上限も適用する。これは資産容量の制限であり、シリアライズ・入力ファイル・デコーダーの一時領域を含むプロセス全体の最大メモリ保証ではない。デコーダーにも128MiBの割り当て目安を設定する。画像は格納された画素方向で扱い、EXIFによる自動回転はまだ行わない。

画像資産はSHA-256で同一バイト列を重複排除し、圧縮データとデコード済みRGBAを不変のArcで共有する。履歴・復旧用スナップショットごとに画像全体を複製しない。削除後もUndo履歴が参照する資産は保持し、文書・履歴・復旧処理から参照されなくなってから解放する。非表示・ロック中の画像はキャンバスのヒットテスト対象から除外する。回転後の画像を逆変換してヒットテストし、軸に平行な外接矩形だけで判定しない。

## 保存・復旧・フォント出力

プロジェクトには画像資産を埋め込み、元画像のパスに依存しない。文書schema version 1に省略可能な`reference_images`を追加し、その内部をversion 1として保存する。資産は`assets`のSHA-256キーとBase64値、配置は`placements`のグリフIDと背面→前面順の配列で保持する。寸法やRGBAは保存せず読込時に元画像から再計算する。格納ハッシュ・全画像の合計画素予算を検証してから画素をデコードし、不明な資産、配置ID重複、孤立資産、不正値、未知バージョンを拒否する。従来の画像なしプロジェクトは空の画像モデルとして読み込む。画像モデルを知らない旧アプリで画像入りプロジェクトを開く互換性は提供しない。自動保存・異常終了後の復旧にも画像資産と配置を含める。読み込み中の異常終了では未確定の画像を文書へ残さない。

TTF／OTF等のフォント出力と実フォントの試し組みにはアタリ画像・変形枠を含めない。画像だけのグリフを輪郭ありとは判定しない。
