# 自動保存・異常終了後の復旧

## 操作

メイン画面上部の復旧アイコンから状態と復旧候補を確認する。異常終了後の次回起動では、候補がある場合に復旧画面を開く。候補の書体名・元のファイル名・保存時刻を表示し、元の保存先はツールチップで確認できる。複数文書の各候補を個別に新しいタブへ復旧できる。[複数文書](multiple-documents.md)。

- 🟢 [Done] 確定済みの編集を、変更が約3秒落ち着いた後に自動保存。1秒ごとのRust workerで判定するため通常3〜4秒程度となる。確定した変更が続く間は約30秒ごとに保存を試みる。
- 🟢 [Done] 書き込み・シリアライズはRust workerで行い、元のプロジェクトへ上書きしない。WebViewの寿命やタイマーに依存しない。IPCは状態と操作のみ。
- 🟢 [Done] ドラッグ中・未確定のペン入力は保存対象外。確定済みの文書から復旧用コピーを作る。起動直後の未編集のサンプル文書は自動保存しない。インポート済み未保存文書は対象。
- 🟢 [Done] 復旧は未保存の新しいプロジェクトとして開く。元のパス・履歴・未確定操作は引き継がない。新しい文書の復旧用コピーを保存できてから元候補を消費する。復旧失敗時は候補を保持する。
- 🟢 [Done] 復旧・新規・読み込みは別タブへ追加する。既存の未保存文書を置き換えず、閉じる・終了時に未保存確認を行う。
- 🟢 [Done] 手動保存で文書が保存済みになった場合、workerが今回のコピーを整理する。正常終了で破棄を承認した場合と明示的な文書破棄でも、対象のコピーだけを整理する。新規／読込やタブ切り替えでは他文書のコピーを消さない。終了確認でキャンセルした場合は保持する。
- 🟢 [Done] 復旧画面を閉じて候補を保留できる。候補は明示的な復旧／破棄まで保持し、別セッションの通常終了では削除しない。
- 🟢 [Done] 復旧データの書込失敗・候補の破損を表示。実行中の別インスタンスの候補は表示・削除・復旧対象にしない。

## 保存先・整合性

Tauriの`app_data_dir()/recovery/`の下に、起動時刻・PID・衝突回避番号からなる独立ディレクトリを各文書のチェックポイントに作る。macOS通常版の例は `~/Library/Application Support/app.fonts.editor/recovery/`。実際のルートは各OSのTauriパス解決に従う。

`session.lock`を標準ライブラリのOSファイルロックで実行中ずっと保持する。プロセスが異常終了するとOSがロックを解放するため、PIDの再利用や前回の終了フラグに依存せず候補を判定できる。

`<document-id>-<revision>.fontproj.json`（旧候補のepochを含む命名形式も互換性を維持）を一時ファイルからsync・atomic renameで保存し、その後に小さな`checkpoint.json`を同じ方法でコミットする。成功後に前世代の本文を整理する。新世代の保存失敗で前の有効なチェックポイントを消さない。文書の上限・検証は通常のプロジェクトと共通（512 MiB）。メタデータは16 KiBまで読み、version・ID・ファイル名を検証する。

手動ファイル操作とworkerの書込はFileGuardで直列化する。チェックポイントは文書ID/revisionで識別し、非表示文書も保存する。画面の編集命令では切り替えごとに更新するepochで古い命令を拒否する。編集が保存途中に進んでも古い保存結果を「手動保存済み」として扱わない。文書を閉じる操作と終了ではworkerとの競合を防いで整理する。

## 制約と次の工程

- 最後に完了した自動保存より後の編集、進行中のドラッグ・ペン入力は失われることがある。大きな文書の処理時間やディスク障害中に時間間隔を保証しない。
- 文書全体のスナップショットを保存する。大きな書体ではメモリ消費とコピー時間が増える。差分ジャーナルと履歴の復旧は 🔴 [Later]。
- sync・atomic renameは使用するが、親ディレクトリのfsyncを含む停電・ストレージ障害での耐久保証はない。書込完了前の一時ファイルや未参照本文は自動で復旧対象にしない。
- 破損した候補は正常な文書として適用しない。元の保存先が外部で変更されていても、そのファイルへ自動で戻さない。
- ⭕️ [Pending] Windows/Linux実機でのロック・強制終了・復旧と大規模書体の連続編集を確認する。

## 検証

自動テスト: 実行中セッションの除外、ロック解放後の候補、文書とUnicodeの保存往復、元ファイルの非変更、無効な新世代での前世代保持、世代更新、明示破棄、破損本文・メタデータ、パス逸脱拒否、debounce・連続編集・未確定操作の除外。

macOSの独立したFonts Recovery QAアプリで送り幅を777へ変更し、自動保存ファイルの値を検証。専用プロセスだけをSIGKILLで強制終了し、再起動時の復旧候補表示・復旧後の送り幅777を画面で確認。明示的に破棄して通常終了した後、チェックポイントが0件であることも確認した。

通常Rustテスト211件、Clippy（`-D warnings`）、型検査・フロントエンドビルド・macOS通常版bundleの生成が成功。
